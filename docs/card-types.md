# 卡型差异与手机 NFC 兼容性

## 四种常见卡型

| 卡型 | UID 是否可写 | 备注 |
| --- | --- | --- |
| 普通 UID 卡（M1 S50） | 否 | 出厂固化，最常见，也最便宜 |
| CUID 卡 | 是 | 用特殊工艺做出可写 UID 块，写 UID 需要专门的写卡器或支持协议的手机 |
| FUID 卡 | 是（一次） | UID 只能写一次，写错就废，但兼容性通常比 CUID 好 |
| Gen2 / UFUID | 是 | 需要「后门指令」解锁后才能写 UID，部分读卡器不支持 |

## 为什么手机写 CUID 会失败

手机 NFC 与 PN532 的差别不在协议，在电气与固件：

1. **天线尺寸**：手机天线为了塞进机身做得很小，耦合距离通常只有 1~2cm，角度敏感
2. **场强与调制深度**：CUID 写 UID 需要的调制深度比普通写块高
3. **控制器差异**：不同厂商的 NFC 控制器（NXP / 博通 / 高通）对 MIFARE 私有写命令的支持程度不一样，
   部分控制器会在固件层直接拒绝非标准写操作
4. **Android 的 NDEF 优先策略**：系统弹「发现标签」时会先尝试 NDEF 解析，
   时序上打断了自定义 APDU 交互

这四条叠加起来，表现出来就是：**同一张 CUID，A 手机能写，B 手机写不了，而 PN532 两个都能写。**

## 实测建议

- 面向「必须有 UID」的场景，优先选 FUID，兼容性稳定，代价是只有一次机会
- 需要批量操作，用 PN532 + 独立写卡器，别指望手机
- 写之前在扇区 0 之外的块先做一次写入测试，确认卡片不是只读锁定
- 记录每张卡的 UID 与写入时间，出问题能回溯

## 关于密钥复用

门禁系统批量下发卡片时，为了省事往往全楼共用同一套密钥。
所以从一张卡上恢复出的 Key A，通常在其余卡上同样有效。
这不是攻破，是部署问题。
